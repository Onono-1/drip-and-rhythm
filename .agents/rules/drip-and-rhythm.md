# DRIP & RHYTHM Workspace Guardrails

These rules reinforce the non-negotiable constraints from `AGENTS.md`, `MASTER_PROMPT.md`, and the approved consolidated project decisions:

1. **Instruction Priority**: Consolidated project decisions & approved plan > `MASTER_PROMPT.md` > architecture & security rules > `AGENTS.md` & workspace rules > approved design system > installed design skills.
2. **Native Runtimes Only (Finalized Local Stack)**: Never introduce Docker, Docker Compose, Dockerfiles, container CI jobs, Redis, Celery, or external object storage. Use the already-installed native runtimes without downgrading or reinstalling: Python `3.15.0` (`backend/.venv`, latest stable Django `6.1.x` supporting Python 3.15), Node.js `26.13.0` + npm `11.20.0` (`npm.cmd`/`npx.cmd` on Windows PowerShell — never weaken execution policy), PostgreSQL `18.7` (`localhost:5432`, DB `drip_and_rhythm`, least-privilege role `drip_app`, isolated `drip_test` — never `postgres` runtime role, never SQLite, never expose DB passwords in chat/code/logs), and separate native email worker (`python manage.py process_email_jobs`). Defer final Render production runtime choices to Phase 10.
3. **Single Authoritative Backend**: All authentication, authorization, invitation lifecycle, uniqueness, PDF/QR/artwork generation, email queuing, and audit logging live in Django. Next.js is strictly frontend SSR, metadata, UI, and approved `/api/:path*` proxying (preserving cookies, CSRF, binary streams, and raw webhook bodies).
4. **One Link · One Email · One Invitation · One Admission**:
   - Enforce email uniqueness, global/per-admin quotas, and single admission with PostgreSQL constraints and canonical lock ordering (`Event` -> `User` -> `Invitation` -> `EmailDelivery`).
   - Keep claim, admission (`DRIP1:<token>`), social sharing, and claim receipt (`drip_claim_receipt`, configurable event-aware lifetime, invalidated on revocation/email correction) credentials strictly isolated and hashed at rest.
   - Never consume invitations on `GET`, never leak guest PII on already-claimed/duplicate responses, and never place private credentials or QR codes on public sharing pages or artwork.
5. **Authentic Branding, Design Skills & Animation Boundaries**: Match `assets/event-poster.jpeg` (`1024×1024`; Midnight Brown `#190D08`, Dark Chocolate `#421509`, Burnt Orange `#E85D19`, Sunset Orange `#FF8C32`, Golden Amber `#FFBE55`, Champagne Gold `#F5CE86`, Warm Ivory `#FFF3E0`, Deep Red `#A51B12`; local `Anton`, `WindSong`, `Montserrat`, `Noto Sans`). Never fabricate organizer logos or unconfirmed venue/time data. Load the 4 installed skills (`.agents/skills/{frontend-design,design-taste-frontend,scroll-craft,impeccable}`) selectively by phase; keep `scroll-craft` strictly on `/`; use Motion + native CSS only (no GSAP/Lenis/Three.js/WebGL without approval); no scroll hijacking or heavy animations in forms, admin, or scanner views.
6. **Verification Honesty & External Action Guardrails**: Run concurrency tests against actual PostgreSQL 18.7, decode real QRs from rendered PDFs, verify UI visually across `320px–1920px` in the browser, distinguish mocked vs live verification, and never push to GitHub, deploy, or provision paid services without explicit user authorization.
